# 贴图排版规范

## 一、画布

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 默认尺寸 | `1080x1440` | 3:4，公众号次图、朋友圈、小红书都安全 |
| 竖屏信息流 | `1080x1920` | 9:16，抖音/视频号封面、小红书全屏 |
| 输出倍率 | `--scale 2` | 实际像素 2160x2880，微信压缩后仍清晰 |
| 内边距 | 宽度 8.2% | 由脚本按画布自动计算 |
| 格式 | `.png` 默认 / `.jpg` | JPG 需 Pillow，缺失时脚本自动保持 PNG |

## 二、卡片类型与字段

每一张卡是一个对象，`type` 决定版式。所有文字字段支持极简富文本：
`**加粗**` → 粗体，`[[高亮]]` → 主题色高亮块，`\n` → 换行。

### `cover` 封面
```json
{"type":"cover","kicker":"AI 工作流","title":"主标题第一行\n第二行","subtitle":"一句话副标题"}
```
- `kicker`：≤ 6 字标签，落在胶囊徽章里
- `title`：≤ 16 字，用 `\n` 手动断行，字号按字数自动分档
- `subtitle`：≤ 24 字，缺省则不显示
- 内容垂直居中，不显示页码，只显示署名

### `points` 要点（核心问题 / 关键结论）
```json
{"type":"points","heading":"这次解决了什么","sub":"可选副标题","items":[{"t":"短标题","d":"一句说明"}]}
```
- `items` 最多 5 条，超过请拆卡
- `t` ≤ 10 字，`d` ≤ 45 字
- 编号 01/02/03 自动生成，不用手写

### `quote` 金句（关键转折）
```json
{"type":"quote","text":"真正省时间的不是 AI 帮你写，[[而是这套流程不用你再想一遍]]","who":"—— 本次会话"}
```
- `text` ≤ 60 字，用 `[[ ]]` 标出要加亮的那半句（只标一处）
- `who` 可选，≤ 16 字
- 一篇文章配 1 张金句卡足够，多了廉价

### `checklist` 清单（可复用经验）
```json
{"type":"checklist","heading":"可复用的经验","items":["先确认素材源在哪，再谈自动化"]}
```
- `items` 最多 7 条，每条 ≤ 22 字
- 每条必须能独立成立，不要写成上下文依赖的半句

### `steps` 流程
```json
{"type":"steps","heading":"四步跑通","items":[{"t":"第一步","d":"说明"}]}
```
- 最多 5 步，编号从 1 开始

### `conclusion` 结论（收尾）
```json
{"type":"conclusion","heading":"写在最后","body":"一段话收口，≤ 90 字","highlight":"[[一句结论]]","tags":["#AI工作流"]}
```
- `highlight` 用强调框呈现，≤ 22 字
- `tags` 最多 6 个，自动排成标签行

## 三、套系设计

### 标准 5 张（默认）
| 序号 | 类型 | 承担什么 |
| --- | --- | --- |
| 01 | cover | 结果前置，勾住人 |
| 02 | points | 这次到底解决了什么（核心问题） |
| 03 | quote | 关键转折的那句话（金句） |
| 04 | checklist | 可复用经验清单 |
| 05 | conclusion | 结论 + 互动触点 |

### 精简 3 张
`cover` → `points` → `conclusion`。适用于素材较薄的会话。

### 单张
只用 `quote`，做金句卡片配文转发。

## 四、主题色板

| 主题 | `--theme` | 适合 |
| --- | --- | --- |
| 珊瑚粉 | `coral`（默认） | 个人号、生活方式、随笔 |
| 黑白极简 | `ink` | 观点评论、严肃内容 |
| 深蓝科技 | `tech` | 技术拆解、产品分析 |
| 薄荷绿 | `mint` | 工具教程、效率方法 |
| 暖阳黄 | `sun` | 经验清单、生活记录 |

深色主题（`tech`）会自动切换为浅色文字，正文与背景对比度由模板保证，不要手动改字色。

## 五、排版铁律

1. **一屏一个观点**。塞不下就拆卡，不要缩小字号。
2. 每张卡只保留一处高亮；高亮多了等于没高亮。
3. 数字、编号、破折号风格统一（中文内容用中文标点）。
4. 标题断行处语义完整，不要在「的」「了」后面断。
5. 卡片底部统一署名（`brand`），页码 `04 / 05` 自动生成。
6. 不要在卡里放二维码、复杂表格、超过 2 行的副标题。
7. 渲染后必看首尾两张图，检查裁切与留白。

## 六、命令行

```bash
# 标准渲染
python render_cards.py --data cards.json --out-dir ./cards --theme coral --scale 2

# 小红书竖屏比例
python render_cards.py --data cards.json --out-dir ./cards --size 1080x1920 --theme ink

# 输出 JPG + 额外拼一张长图（需要 Pillow）
python render_cards.py --data cards.json --out-dir ./cards --format jpg --merge

# 保留中间 HTML 便于手动微调版式
python render_cards.py --data cards.json --out-dir ./cards --keep-html
```

返回 JSON 含 `files` 列表；`ok=false` 时看 `reason` 定位问题（多为浏览器缺失或数据为空）。

```json
    {"type": "points", "heading": "这次解决了什么", "sub": "不是写总结，是做资产",
     "items": [
       {"t": "对话即素材", "d": "会话记录存在本地，能被程序直接读出来"},
       {"t": "检查前置条件", "d": "没有历史记录就不启动"},
       {"t": "两种产物", "d": "文章走 Markdown，贴图走模板渲染"}
     ]},
    {"type": "quote", "text": "真正省时间的不是 AI 帮你写，[[而是这套流程不用你再想一遍]]", "who": "—— 本次会话"},
    {"type": "checklist", "heading": "可复用的经验",
     "items": ["先确认素材源在哪，再谈自动化", "抽取时过滤工具调用与思维链", "贴图用 HTML 模板截图，文字永远清晰"]},
    {"type": "conclusion", "heading": "写在最后", "body": "做一次，之后每次收尾都能一键出稿。", "highlight": "[[会话结束的那一刻，就是内容开始的那一刻]]", "tags": ["#AI工作流", "#内容复用"]}
  ]
}
```
